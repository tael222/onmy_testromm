# 계산식 점검용 내부 도구 PRD (Formula Checker)

## 1. 개요
본 문서는 Python 기반 계산 지원 모듈(WAI)을 사용하여 작성된 **개별 계산식(Process / Structure / Equipment)**이
내부 규칙에 맞게 구현되었는지 검증하고, Unity 환경 없이도 계산 결과를 재현·분석하기 위한
**계산식 점검용 내부 도구**의 Product Requirements Document(PRD)이다.

본 도구는 모듈 자체의 품질을 검증하거나 계산식을 자동 생성하는 목적이 아니라,
이미 정의된 계산식을 대상으로 **문법 검증 → 단독 실행 → exec 기반 조합 실행**까지
실제 실행 구조를 그대로 재현·확인하는 데 목적이 있다.

---

## 2. 배경 및 문제 정의
현재 WAI 기반 계산식은 Python으로 작성되지만, 실행 및 검증은 Unity 환경에 강하게 의존한다.
또한 계산식 실행 구조상 다음과 같은 구조적 제약이 존재한다.

- 계산식은 개별 Python 스크립트(.py) 단위로 작성되며, **단독 실행을 통한 문법 및 기본 로직 검증**이 선행되어야 한다.
- 공정(Process) 계산식 내부에서 구조물(Structure) 및 기계(Equipment) 계산식은
  **문자열(script) 형태로 전달**되어 Python의 `exec()` 메서드를 통해 직접 실행된다.
- 이로 인해 개별 계산식만 검증할 경우, 실제 공정 계산 흐름에서 발생하는 오류를 사전에 파악하기 어렵다.

따라서 본 도구는  
**① 개별 계산식 단독 검증**과  
**② exec 기반 계산식 조합을 포함한 전체 공정 계산 테스트**  
를 모두 수행할 수 있어야 한다.

## 3. 사용자 정의 및 핵심 목적
### 3.1 사용자
- 계산식을 작성·수정하는 개발자
- 계산 결과 관련 내부 문의를 분석·대응하는 담당자

외부 고객 및 일반 사용자는 본 도구의 사용자 범위에 포함하지 않는다.

### 3.2 핵심 목적
- 계산식 README 규칙(함수 정의, 컨테이너 사용 규칙 등) 준수 여부 확인
- 개별 계산식의 문법 오류 및 기본 로직 검증
- 공정 계산식에서 구조물·기계 계산식이 exec 기반으로 정상 결합·실행되는지 확인
- Unity 없이 계산 결과를 수치 기반으로 재현 및 비교

## 4. 기능 요구사항
### 4.1 개별 계산식 단독 검증 (Syntax & Logic Check)
- Python 문법 오류 검사 (Python 3.12 이상 기준)
- 필수 함수 정의 여부 확인
  - Structure 계산식
    - `forward_calculate`
    - `reverse_calculate`
    - `level_calculate`
  - Equipment 계산식
    - `forward_calculate`
- 컨테이너 사용성 점검
  - DCN, DCR, DCP, DSP, DEP 등의 컨테이너가
    `SingleValue`, `RangedValue` 등 올바른 ValueObject 타입을 사용하는지 확인

### 4.2 조합된 전체 공정 계산 테스트 (Integration Test)
- exec() 실행 재현
  - 공정 계산식 내에서 StructureValue / EquipmentValue에 전달된
    계산식 스크립트 문자열을 내부적으로 `exec()`로 실행
- 데이터 흐름 검증
  - 공정 계산 결과가 구조물·기계 계산식의 inputs로 정상 전달되는지 확인
  - exec 실행 결과가 다시 공정 컨테이너(DCP 등)에 반영되는지 확인
- 상태 유지 검증
  - 재계산 시 IValueObject 인스턴스는 유지되고,
    기본 타입(value) 값만 재할당되는 구조인지 확인

### 4.3 입력 및 출력 제어
- 입력값 수동 설정
  - Unity 없이 DCN, DSP, DEP 등 입력 컨테이너 값 직접 정의
- 중간값 및 결과 출력
  - 계산 과정 중 중간 계산값
  - 최종 결과(SingleValue.value, unit 등) 출력
- 오류 정보 제공
  - exec 실행 중 예외 발생 시
    오류 발생 스크립트, 라인, 원인 정보 제공

---

## 5. 비기능 요구사항 및 기술적 제약
- 재현성
  - 동일 입력 조건에 대해 항상 동일한 계산 결과를 재현할 수 있어야 한다.
- 인스턴스 스코프
  - 각 실행은 독립된 인스턴스 ID(`setInstanceId`) 환경을 모사하여
    데이터가 섞이지 않도록 한다.
- 전역 컨테이너 관리
  - STD 등 전역 컨테이너의 영향 범위를 고려해야 한다.
- exec 실행 구조
  - exec 사용으로 인해 실행 컨텍스트 관리가 중요하며,
    실행 단계별 로그 및 오류 추적이 가능해야 한다.

---

## 6. 주요 사용 시나리오
1. 점검 대상 공정 계산식과 연관된 구조물·기계 계산식을 선택한다.
2. 각 계산식을 단독 실행하여 문법 및 기본 로직 오류를 먼저 확인한다.
3. 설계 조건(DCN, DSP 등)을 수동으로 입력한다.
4. 전체 공정 계산 테스트를 실행하여 exec 기반 연쇄 계산을 수행한다.
5. 중간값 및 최종 결과를 확인하고 수정 전·후 결과를 비교한다.

## 7. 비범위 (Out of Scope)
- 외부 사용자 제공 UI
- 사용자 친화적 인터페이스 설계
- 배포 및 설치 자동화
- 계산식 자동 생성 기능
- exec 구조 자체에 대한 리팩터링

---

## 8. 성공 기준 (Acceptance Criteria)
- Unity 없이 exec 기반 조합 계산 결과를 수치로 확인할 수 있다.
- 계산식 파일의 문법 오류 및 필수 함수 미정의 지점을 즉시 식별할 수 있다.
- 실제 내부 문의에서 제기된 계산 결과를 동일 입력 조건에서 재현할 수 있다.
- 계산식 결합 과정에서 발생한 오류 위치를 명확히 추적할 수 있다.
