# oh-my-claudecode Plugin Test Plan

## 1. 테스트 개요

### 1.1 목적
oh-my-claudecode 플러그인의 효과를 정량적/정성적으로 분석하여 실제 개발 생산성 향상 여부를 검증한다.

### 1.2 테스트 대상
- **플러그인 버전**: oh-my-claudecode (현재 설치 버전)
- **테스트 프로젝트**: Formula Checker (PRD.md 기반)
- **비교 대상**: 플러그인 사용 vs 미사용

## 3. 테스트 시나리오

### 3.1 Test A: 프로젝트 완성 일괄 실행
**목표**: PRD.md 기반으로 Formula Checker 프로젝트를 처음부터 완성

| 단계 | 작업 내용 | 측정 항목 |
|------|----------|----------|
| A-1 | 프로젝트 구조 설계 | 토큰, 시간 |
| A-2 | 핵심 기능 구현 | 토큰, 시간, 코드량 |
| A-3 | 테스트 작성 | 토큰, 테스트 커버리지 |
| A-4 | 문서화 | 토큰, 문서 품질 |

**실행 방식**:
- `workplace/with-omc/test-a-{timestamp}/` - 플러그인 사용
- `workplace/without-omc/test-a-{timestamp}/` - 플러그인 미사용

### 3.2 Test B: Feedback 반영 테스트
**목표**: 완성된 프로젝트에 변경 요청을 반영하는 과정 분석

| Feedback 유형 | 설명 | 예시 |
|--------------|------|------|
| 기능 추가 | 새로운 기능 요청 | "JSON 결과 내보내기 추가" |
| 버그 수정 | 오류 수정 요청 | "exec 오류 추적 누락 수정" |
| 리팩토링 | 구조 개선 요청 | "컨테이너 검증 로직 분리" |
| 스펙 변경 | 요구사항 변경 | "Python 3.11 호환성 추가" |

### 3.3 Test C: 반영 방식 분석
**목표**: 변경 요청 시 부분 수정 vs 전체 재시작 패턴 분석

| 분석 항목 | 확인 내용 |
|----------|----------|
| 기존 코드 분석 여부 | 변경 전 코드 읽기/이해 과정 |
| 영향 범위 파악 | 변경이 미치는 범위 분석 |
| 수정 전략 | 부분 수정 / 파일 재작성 / 전체 재시작 |
| 의존성 처리 | 연관 파일 자동 업데이트 여부 |

### 3.4 Test D: Skill 사용 분석
**목표**: oh-my-claudecode가 제공하는 skill들의 실제 활용도 분석

| Skill | 사용 빈도 | 효과 | 비고 |

| /ralph | - | - | 반복 실행 |

| /code-review | - | - | 코드 리뷰 |
| /security-review | - | - | 보안 검토 |
| /deepsearch | - | - | 코드 탐색 |
| 기타 | - | - | - |

## 5. 평가 기준

### 5.1 정량적 지표
| 지표 | 설명 | 가중치 |
|------|------|--------|
| 토큰 효율성 | 동일 결과물 대비 토큰 사용량 | 30% |
| 완성도 | PRD 요구사항 충족률 | 25% |
| 코드 품질 | 린트, 타입 오류, 테스트 커버리지 | 20% |
| 반영 속도 | Feedback 반영에 필요한 토큰/턴 수 | 15% |
| 정확성 | 불필요한 재작업 발생 빈도 | 10% |

### 5.2 정성적 지표
- 워크플로우 자연스러움
- 에러 복구 능력
- 컨텍스트 유지력
- 사용자 개입 필요 빈도
