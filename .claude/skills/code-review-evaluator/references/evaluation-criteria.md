# 평가 기준 상세

## 1. 로직 정확성 (Logic Accuracy) - 가중치 25%

PRD에 명시된 요구사항이 코드에 정확하게 구현되었는지 평가.

### 평가 항목
- PRD의 핵심 기능이 올바르게 동작하는가
- 엣지 케이스 처리가 적절한가
- 조건문/반복문의 논리가 정확한가
- 데이터 흐름이 의도대로 작동하는가
- 논리적 함정(무한 루프, 도달 불가 코드 등)이 없는가

### 등급 기준
| 등급 | 점수 | 기준 |
|------|------|------|
| A | 90-100 | 모든 핵심 로직이 정확, 엣지 케이스 처리 완벽 |
| B | 75-89 | 핵심 로직 정확, 일부 엣지 케이스 미처리 |
| C | 60-74 | 기본 로직은 동작, 몇몇 논리 오류 존재 |
| D | 0-59 | 핵심 로직에 중대한 오류 존재 |

---

## 2. 완결성 (Completeness) - 가중치 25%

PRD 대비 기능 구현 완료율 평가.

### 평가 항목
- PRD에 명시된 기능이 모두 구현되었는가
- 필수 기능 vs 선택 기능 구현 비율
- TODO/FIXME 주석으로 남겨진 미완성 부분
- 스텁(stub) 또는 하드코딩된 임시 코드 존재 여부

### 등급 기준
| 등급 | 점수 | 기준 |
|------|------|------|
| A | 90-100 | PRD 요구사항 95% 이상 구현 |
| B | 75-89 | PRD 요구사항 80-94% 구현 |
| C | 60-74 | PRD 요구사항 60-79% 구현 |
| D | 0-59 | PRD 요구사항 60% 미만 구현 |

---

## 3. 구조적 연결성 (Structural Connectivity) - 가중치 15%

클래스, 함수, 변수 간의 연결이 매끄럽고 논리적인지 평가.

### 평가 항목
- 클래스/모듈 간 의존성이 명확한가
- 함수/메서드 간 호출 관계가 적절한가
- 변수 스코프가 올바르게 관리되는가
- 순환 참조나 불필요한 의존성이 없는가
- 인터페이스/추상화 수준이 적절한가

### 등급 기준
| 등급 | 점수 | 기준 |
|------|------|------|
| A | 90-100 | 모듈화 우수, 의존성 명확, 결합도 낮음 |
| B | 75-89 | 구조 양호, 일부 개선 여지 있음 |
| C | 60-74 | 기본 구조는 있으나 결합도 높음 |
| D | 0-59 | 구조적 문제 심각, 스파게티 코드 |

---

## 4. 문법적 정확성 (Syntax Correctness) - 가중치 10%

컴파일/실행 오류 없이 코드가 동작하는지 평가.

### 평가 항목
- 문법 오류 없이 컴파일/실행 가능한가
- 타입 오류가 없는가
- import/using 문이 올바른가
- 괄호, 세미콜론 등 구문 요소가 정확한가

### 등급 기준
| 등급 | 점수 | 기준 |
|------|------|------|
| A | 90-100 | 문법 오류 없음 |
| B | 75-89 | 경미한 오류 1-2개 (쉽게 수정 가능) |
| C | 60-74 | 여러 오류 존재하나 핵심 부분은 동작 |
| D | 0-59 | 컴파일/실행 불가능한 수준의 오류 |

---

## 5. 효율성 (Efficiency) - 가중치 10%

알고리즘과 자원 사용의 최적화 수준 평가.

### 평가 항목
- 시간 복잡도가 적절한가
- 공간 복잡도가 적절한가
- 불필요한 반복/재계산이 없는가
- 메모리 누수 가능성이 없는가
- 적절한 자료구조를 사용했는가

### 등급 기준
| 등급 | 점수 | 기준 |
|------|------|------|
| A | 90-100 | 최적화 우수, 효율적인 알고리즘 사용 |
| B | 75-89 | 양호한 효율성, 소소한 개선 여지 |
| C | 60-74 | 동작하나 비효율적인 부분 존재 |
| D | 0-59 | 명백한 성능 문제 존재 |

---

## 6. 명명 규칙 (Naming Convention) - 가중치 10%

변수, 함수, 클래스 등의 네이밍 컨벤션 준수 여부 평가.

### Python 기준
- 변수/함수: `snake_case`
- 클래스: `PascalCase`
- 상수: `UPPER_SNAKE_CASE`
- private: `_prefix`

### C# Unity 기준
- 변수: `camelCase`
- 함수/메서드: `PascalCase`
- 클래스: `PascalCase`
- private 필드: `_camelCase` 또는 `m_PascalCase`
- 상수: `PascalCase` 또는 `UPPER_CASE`

### 공통 평가 항목
- 의미 있는 이름을 사용했는가
- 약어 사용이 적절한가
- 일관된 명명 패턴을 따르는가

### 등급 기준
| 등급 | 점수 | 기준 |
|------|------|------|
| A | 90-100 | 명명 규칙 완벽 준수, 명확한 이름 |
| B | 75-89 | 대체로 준수, 일부 불명확한 이름 |
| C | 60-74 | 일부 규칙 미준수, 의미 불명확 |
| D | 0-59 | 명명 규칙 무시, 이해하기 어려움 |

---

## 7. 일관성 (Consistency) - 가중치 5%

코드 전반의 스타일 통일성 평가.

### 평가 항목
- 들여쓰기가 일관적인가
- 줄바꿈/공백 스타일이 통일되어 있는가
- 주석 스타일이 일관적인가
- 코드 구조 패턴이 통일되어 있는가
- 에러 처리 방식이 일관적인가

### 등급 기준
| 등급 | 점수 | 기준 |
|------|------|------|
| A | 90-100 | 완벽한 일관성, 하나의 스타일 |
| B | 75-89 | 대체로 일관적, 소소한 불일치 |
| C | 60-74 | 부분적 불일치, 여러 스타일 혼재 |
| D | 0-59 | 일관성 없음, 읽기 어려움 |

---

## 종합 점수 계산

```
종합점수 = (로직 × 0.25) + (완결성 × 0.25) + (구조 × 0.15) + 
          (문법 × 0.10) + (효율성 × 0.10) + (명명 × 0.10) + (일관성 × 0.05)
```
